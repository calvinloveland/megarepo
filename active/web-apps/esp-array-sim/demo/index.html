Overview

This project lets you turn a handful of ESP32 boards into a self-organizing wireless 5.1 surround system. No setup, no calibration routine, no wiring the room — just scatter the nodes around, press a button, and they figure out where they are using sound, then render the audio accordingly.

One node = one ESP32 + one speaker + one microphone. The mesh self-localizes by emitting calibration chirps and measuring time-of-arrival at every other node's microphone — an acoustic version of GPS. Once positions are known, the nodes pan the standard 5.1 channels onto whichever layout they actually found.

How it works

Scatter nodes → Coarse WiFi sync → Chirp sweep → TOA estimation → Joint solve → 5.1 panning

Each node takes a turn playing a known linear-FM chirp while every other node listens with its microphone. A matched-filter cross-correlation recovers the time-of-flight, and a joint Levenberg–Marquardt solver recovers all node positions + clock offsets simultaneously. The mesh then maps 5.1 channels onto the discovered layout using cosine-power panning, with per-speaker delay/gain compensation so every channel arrives at the listening position at the same time and equal loudness.

The entire algorithm was developed and validated in a browser-based simulator before any firmware was written. The same math powers both the simulator and the real C code running on the ESP32.

Step-by-step assembly

  1. Connect the I2S DAC (speaker) to the ESP32.
    Most MAX98357A breakouts expose 6 or 7 pins depending on board variant. For basic mono playback you only need the five required connections below; boards may also expose GAIN and/or SD/EN as optional control pins.
    Required MAX98357A pins
    VIN → 5V / VBUS (preferred for louder output; 3.3V also works with lower power)
    GND → GND
    BCLK / BCK → GPIO 26
    LRC / WS / LRCK → GPIO 25
    DIN → GPIO 22
    Optional breakout pins
    GAIN — leave floating for default gain, or strap per board docs
    SD / EN — pull high (often already tied high on breakout) to enable amp
    L/R — if present on your variant, set mono channel selection per board docs
    Kconfig defaults
    CONFIG_ESP_ARRAY_I2S_SPEAKER_BCK_PIN=26
    CONFIG_ESP_ARRAY_I2S_SPEAKER_WS_PIN=25
    CONFIG_ESP_ARRAY_I2S_SPEAKER_DATA_PIN=22
    The speaker output connects to the MAX98357A screw terminals. Use a small 4Ω–8Ω speaker. If your breakout exposes GAIN or SD, start with the board's default wiring (or leave them unconnected if the vendor docs say the breakout already biases them correctly).
  2. Connect the I2S microphone to the ESP32.
    The INMP441 breakout has six pins; you need four:
    INMP441
    VDD → 3.3V
    GND → GND
    SCK → GPIO 19
    WS → GPIO 21
    SD → GPIO 23
    L/R → GND (left channel)
    Kconfig defaults
    CONFIG_ESP_ARRAY_MIC_I2S_SCK_PIN=19
    CONFIG_ESP_ARRAY_MIC_I2S_WS_PIN=21
    CONFIG_ESP_ARRAY_MIC_I2S_DATA_PIN=23
  3. Power the board.
    Connect the ESP32 to a USB power source (5V, 1A minimum). The MAX98357A and INMP441 draw power from the ESP32's 3.3V rail, which is fine for a single node.
  4. Repeat for each node.
    Build 6–8 identical nodes. Each uses the same pinout, so the same firmware binary works on every board. The mesh self-localizes regardless of which node is which.
  5. Optional: mount on a custom PCB.
    Once the design is stable, the breadboard wiring can be transferred to a simple breakout PCB (KiCad / EasyEDA). The pin assignments stay the same.

Software setup

All firmware tooling is pre-configured in the repo. On this NixOS host:

cd active/web-apps/esp-array-sim
npm run firmware:bootstrap-idf   # Check out ESP-IDF (done once)
nix-shell                        # Enter the firmware dev shell
source ./.esp-idf/activate-idf.sh        # (and exit)  # Add ESP-IDF to PATH
steam-run bash -lc "source ./.esp-idf/activate-idf.sh && cd firmware && idf.py build"

For a standard Linux/macOS environment (non-NixOS):

cd active/web-apps/esp-array-sim
bash bin/bootstrap-esp-idf.sh --checkout-only  # Clone ESP-IDF
bash bin/bootstrap-esp-idf.sh --install-tools  # Install toolchain + Python deps
source ./.esp-idf/activate-idf.sh              # Activate the ESP-IDF environment
cd firmware && idf.py build                    # Build

Running it

🧪 1. Test the simulator

No hardware required. Click through the interactive simulator to understand the algorithm and tune parameters before flashing.

Launch simulator →

🔌 2. Flash one node

Connect a single node via USB and verify it boots, plays the calibration chirp, and prints diagnostic output over serial.

cd firmware
idf.py -p /dev/ttyUSB0 flash monitor

🌐 3. Flash all nodes

Repeat the flash step for each node. Once all nodes are powered, the mesh coordinator state machine on each board runs the calibration lifecycle autonomously.

🎵 4. Five-channel audio

Once self-localized, the system accepts a 5.1 input stream and maps it to the discovered speaker layout. Connect any audio source via Bluetooth A2DP, USB audio, or line-in to one coordinator node.
