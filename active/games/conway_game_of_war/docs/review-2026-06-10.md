## Issues Found

### 1) Newly added End Turn regression tests are currently broken

**Impact:** `npm test` is red.

Failing tests:

- `tests/end-turn.spec.js:240` — `5 consecutive End Turns without stale lastRem`
- `tests/end-turn.spec.js:247` — `multi-step turn auto-steps complete`
- `tests/end-turn.spec.js:257` — `End Turn then Reset then End Turn works`

Observed failure:

- Each times out waiting for `#end-turn-btn`
- The failure happens before the button click sequence actually starts

Root cause:

- These three tests were appended **outside** the `test.describe('End Turn animation', ...)` block.
- Because of that, they do **not** inherit the suite-local `beforeEach(async ({ page }) => await goToGame(page))` setup.
- As written, they start on a blank page and then wait forever for `#end-turn-btn`.

Recommended fix:

- Move those three tests inside the `End Turn animation` describe block, or
- add explicit `await goToGame(page)` at the start of each top-level test.

---

### 2) One touch Playwright test is flaky / order-dependent

**Impact:** full browser suite is not stable even though the feature itself may work.

Failing test in full suite:

- `tests/touch-gestures.spec.js:374` — `tap on a toggleable cell dispatches a click`

Observed behavior:

- Fails in full suite because `newBg === initialBg`
- Passes when run in isolation

Likely cause:

- The test assumes the target cell's inline background color will definitely change after the tap.
- That is brittle because the chosen cell/state/color path is sensitive to render state and prior assumptions about ownership/aliveness/crop tint.
- The interaction likely works, but the assertion is too coupled to a specific color transition.

Recommended fix:

- Assert on a more stable signal, for example:
  - the `/update_cell?...json=1` request returning 200,
  - a cell class/data attribute change,
  - or a semantic state change derived from the board payload.
- If keeping a visual assertion, choose a cell whose pre/post state is guaranteed by setup rather than inferred from initial board coloring.

### 3) Documentation is stale relative to the current implementation

**Impact:** local docs no longer describe the actual shipped behavior.

`docs/index.md` currently says or implies:

- Medium/Hard AI are stubs
- double-tap zoom exists

But recent implementation work changed that direction:

Recommended fix:

## Coverage Gaps

These are not necessarily failures today, but they are still missing protection.

### 4) No explicit end-to-end test for the original territory-collision regression path

The original bug report was about the game breaking when territories collided.

Current tests exercise long turn chains, but there is still no dedicated Playwright flow that:

- creates two expanding territories,
- forces a collision/combat boundary,
- runs End Turn through the collision,
- verifies the animation chain completes without swap errors/timeouts,
- and confirms the button recovers cleanly.

Recommended test:

- Add a deterministic collision scenario that drives the exact bug path rather than relying on general long-turn coverage.

---

### 5) No explicit browser-level assertion that `/step` count matches Fibonacci progression

Current tests confirm completion, but they do not explicitly verify request counts.

A targeted E2E assertion would catch regressions like:

- duplicate `/step` requests,
- skipped `/step` requests,
- or turns that finish early while still reporting success.

Recommended test:

- Track network requests for `/step` and assert expected counts across several turns:
  - turn 1 → 0 step requests
  - turn 2 → 0
  - turn 3 → 1
  - turn 4 → 2
  - turn 5 → 4

---

### 6) No end-to-end coverage for the warning/error logging path

The app now logs warnings when waits exceed thresholds, but there is no test confirming that:

- a delayed step emits a warning,
- `/log_error` receives it,
- and the UI still recovers.

This matters because the recent animation work relies on timeout guards for failure detection.

## Suggested Priority

3. Add one deterministic territory-collision E2E test.
4. Add `/step` request-count assertions for Fibonacci turns.
